# UMA data dictionary

The files `uma build` writes to `docs/data/`. Fields of the release itself are in UMDB's [DATA_DICTIONARY.md](https://github.com/aglucaci/UMDB/blob/main/DATA_DICTIONARY.md); STRIGA's result files are described in its README.

| File | Contents |
| --- | --- |
| `release.json` | `version`, `doi`, `url`, `contract`, `created_utc`, `database_built_utc`, schema and rule versions, `counts` (from the release manifest), `tiers` (BioSamples per eligibility tier), `urban_habitats` ([habitat, urban BioSamples]), `licenses`, `collections`, `files` (path → bytes, SHA-256; `analysis/` files omitted), `analysis` (STRIGA pipeline and status counts), `built_utc` (when UMA built this site) |
| `findings.json` | `available`, `pipeline` (name, version, commit), `input` (analysed database SHA-256, build, rows), `created_utc`, `params`, `status_counts`, and `hypotheses`: one object per registered hypothesis with `id`, `track`, `program`, `title`, `status`, `result`, and when it ran `question`, `caveats`, `results` (key numbers), `figures` and `tables` (paths under `findings/`), `release_only_files`; `method` and `decision_rule` when STRIGA's registry provides them |
| `findings/<ID>/` | STRIGA's figures and tables for that hypothesis, copied unchanged (tables over 5 MB stay in the release download) |
| `studies.json` | `cols` and `rows`: one row per BioProject with `accession`, `title`, `center`, `samples`, `runs`, `urban_samples`, `first_year`, `last_year` (run release years), `countries` (up to three ISO codes, most samples first), `habitats` (up to two urban habitats), `assays` (up to three) |
| `places.json` | `places` (`place_cols`: GeoNames `id`, `name`, `country`, `region`, `lat`, `lon`, `population`, `samples`, `urban_samples`, `studies` = list of BioProjects) and `countries` (`country_cols`: `iso2`, `name`, `continent`, `samples`, `urban_samples`, `studies` = count). Only verified or probable locations are counted; a BioSample shared by two studies counts once |
| `p/<ACC>.json` | One study: `title`, `description`, `center`, `data_type`, `submission_date`; `samples` (`sample_cols`: accession, title, tier, context, collection date and year, country, region, place id and name, location status, lat, lon, submitted location, isolation source, ENVO broad/local/medium, eligibility reason); `runs` (`run_cols`: accession, sample, experiment, assay, strategy, source, layout, platform, instrument, bases, spots, release date, download URL); `sample_projects` for BioSamples that belong to several studies. `_none.json` holds runs without a BioProject |
| `ix/<NN>.json` | Accession lookup, split by the last two digits of the accession (`xx` if none): BioSample → list of BioProjects, run → BioProject |
